# Террор — red_planet

Числовая мера того, насколько игрок себя обнаружил. Без потолка. Складывается из четырёх слагаемых, каждое из которых проходит через свою кривую насыщения.

Место в дизайне — стрелка «Экспансия → Давление» из [игрового цикла](gameplay-loop.md). Стрелка объявлена обязательной, но работала неявно: чем длиннее периметр, тем больше точек соприкосновения. Террор делает эту зависимость измеримой и показанной игроку.

---

## 1. Слагаемые

### Производство

```
raw = поток метала + выработка энергии / 3.6
```

Курс не выдуман: это курс экстрактора (18 энергии на 5 метала), объявленный в дизайне выгодным и целевым. Курс синтезатора сюда не годится — он намеренно невыгоден и означает сброс излишков, а не обмен.

Считается **валовая выработка**, а не сальдо. По сальдо портал, потребляющий энергию, снижал бы показатель: чем ближе победа, тем спокойнее, — а требуется обратное.

### Экспансия

```
raw = Σ по постройкам (вес × коэффициент зоны)
```

Вес лежит в `.toml` постройки, в секции `[terror]`, ключ `expansion`. Не задан — выводится из рода: постройка весит единицу, подвижная сущность ноль. Задавать нужно там, где умолчание неверно: забор весит около 0.05, потому что их много, места они занимают столько же, сколько завод, а угрозы не несут.

Коэффициент зоны берётся по расстоянию от **точки высадки**, а не от текущего центра базы. Центр базы смещается по мере роста, и тогда дальняя постройка со временем сама собой становилась бы ближней — то есть расширение удешевляло бы уже сделанное расширение.

| Зона | Радиус, клеток | Коэффициент |
|---|---|---|
| Высадка | до 8 | 0.2 |
| Средняя | до 15 | 1.0 |
| Фронтир | дальше 15 | 2.5 |

Каркасы не входят: поставленный, но не достроенный каркас ещё ничего не занял и решением не является — его в любой миг можно отменить.

### Мощь армии

```
raw = Σ по подвижным сущностям игрока (мощь)
```

Ключ `army_power` в той же секции. Умолчание — единица у подвижного со стволом, ноль у прочих. Строитель армией не является; турель считается по экспансии, иначе вошла бы в показатель дважды. Географии здесь нет: положение подвижной сущности меняется постоянно.

Величина общая для обеих сторон. У игрока она складывается в это слагаемое, у противника той же мерой считается занятое место в бюджете постоянного давления, поэтому числа сторон сопоставимы и настраиваются в одних единицах.

### Время партии

```
raw = сколько идёт партия, секунд
```

Единственное слагаемое, на которое игрок не влияет ничем, и потому единственное, которое не про обнаружение. Его роль — пол, ниже которого давление не опускается: без него выгодной оказалась бы стратегия не строить вовсе, а она обесценивает первый узел петли. Вес держится ниже прочих, чтобы набежавшее само не перебивало сделанное игроком.

### Что в показатель не входит и почему

База и коммандер обнулены явно. Оба выданы, а не построены, и решением игрока не являются — считать их значило бы стартовать с террора, который ничем не заработан. Собственная выработка коммандера при этом в производство входит: производство меряется потоком, а не составом, и отдельного знаменателя у него нет.

## 2. Кривые

```
t = raw / reference
вклад = (t ≤ 1 ? curve(t) : curve(1) + (t − 1) × tail) × weight
```

**Кривые нужны не для того, чтобы гасить прибавку.** База растёт примерно экспоненциально: каждый новый генератор ускоряет постройку следующего. Вогнутая кривая переводит экспоненциальный рост входа в примерно линейный рост давления. Без неё поздняя партия получила бы волны, несоизмеримые с возможностями игрока, а показатель перестал бы что-либо различать.

**Асимптоты у кривой быть не должно.** Насыщение с потолком означает, что после некоторого размера расширение бесплатно, — а это отменяет решение «расширяться или нет». Поэтому за опорным значением кривая продолжается прямой с наклоном `tail`.

Опорные значения и веса на первый заход:

| Слагаемое | reference | weight | tail |
|---|---|---|---|
| Производство | 200 | 20 | 0.15 |
| Экспансия | 150 | 45 | 0.15 |
| Армия | 60 | 35 | 0.15 |
| Время | 900 с | 15 | 0.15 |

Распределение весов намеренно неравное. Вес производства ниже остальных: иначе выгодной становится стратегия отказа от экономики, а она обесценивает первый узел петли.

Ожидаемый ход показателя при этих числах — от 15 в начале партии до 90 в конце. Выработка энергии за то же время растёт в пятнадцать раз, число построек в сорок пять: в этом и состоит работа кривых.

## 3. Сглаживание

```
smoothed += (raw − smoothed) × (1 − exp(−Δt / τ)),   τ = 60 с
```

Показатель есть уровень, а не накопитель: при потере построек он падает. Если бы бюджет волны читал мгновенное значение, снос собственного форпоста перед волной облегчал бы её, и появилась бы вырожденная тактика. Задержка растягивает падение настолько, что намеренное разрушение не окупается; рост при этом учитывается почти сразу.

Игроку показывается мгновенное значение. Сглаженное — внутренняя величина.

---

## 4. Где что лежит

| Что | Где | Почему там |
|---|---|---|
| Веса отдельных сущностей | `resources/**/*.toml`, секция `[terror]` | правятся текстом, как и прочие числа сущности |
| Кривые, опорные значения, веса, зоны | `resources/tuning/terror.tres` | кривую рисуют мышью; редактор для этого в движке уже есть |
| Перевод очков в бюджет давления | `resources/tuning/pressure.tres` | мера и следствие подбираются по разным признакам |
| Подсчёт | `scripts/pressure/TerrorSystem.cs` | |
| Ряды по ходу партии | `scripts/data/Projections/TimeSeriesProjection.cs` | |
| Плашки | `scripts/ui/TerrorBar.cs` | |

Разделение хранения проведено по способу настройки, а не по роду данных. Заводить свой редактор кривых незачем: ресурс `Curve` правится в инспекторе.

Ряды пишутся раз в секунду в именованные каналы `terror.raw`, `terror.smoothed`, `terror.production`, `terror.expansion`, `terror.army`, `terror.time`. Механизм общий, не привязанный к террору: доход, когда до него дойдёт очередь, пишется теми же каналами `income.metal` и `income.energy` — требование «по графику дохода видно историю партии» уже стоит в игровом цикле.

## 5. Куда показатель уходит

**Бюджет постоянного давления.** Сглаженное значение читает `PressureSystem` и переводит в допустимую суммарную мощь противника на карте:

```
бюджет = max(сглаженный террор × power_per_terror, минимум)
```

Коэффициент перевода нужен потому, что величины разной природы: очки террора складываются из слагаемых, прошедших через кривые, а мощь считается в единицах ключа `army_power`. Приравнять их напрямую нельзя. Минимум задан на первые секунды партии, пока слагаемое времени ещё около нуля.

Слагаемое времени внутри показателя заменило собой отдельное слагаемое времени в бюджете, которое раньше предполагалось складывать снаружи. Сложение осталось сложением, но перенеслось на уровень выше: пол задаётся внутри террора, а бюджет получает уже готовую сумму.

## 6. Чего ещё нет

**Связи волн с показателем.** Волны реализованы (`WaveSystem`, файлы в `resources/waves/`) и приходят поверх бюджета: их юниты помечены `PressureOrigin.Wave` и в занятое место не входят. Но бюджет отдельной волны по умолчанию от террора не зависит — он задан числом в её файле, а связь появляется только там, где автор волны задал `army_power_per_terror` отличным от нуля. Показатель при этом решает, какие волны вообще применимы: границы задаются ключом `terror_range`. Насколько такого разделения достаточно, покажет калибровка на партиях.

**Показа истории.** Ряды копятся, потребителя у них пока нет. Первым потребителем предполагается отладочное окно для настройки кривых, а не элемент интерфейса игрока: график террора без объяснения причин колебаний скажет игроку мало, а трёх плашек с текущими значениями ему достаточно.

**Разбивки по наведению.** Коэффициент 0.05 у забора остаётся знанием разработчика, пока игрок не может посмотреть, из чего сложился его показатель.
