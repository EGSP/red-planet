# Редактор контента

Вкладка главного экрана Godot **Content** (рядом с 2D / 3D / Script). Плагин: `addons/content_editor/`. Интерфейс редактора на английском.

## Для агентов: где что лежит

| Часть | Путь | Роль |
|-------|------|------|
| Плагин | `addons/content_editor/ContentEditorPlugin.cs` | вкладка главного экрана, подписка на FilesystemChanged |
| UI | `addons/content_editor/ContentEditorMain.cs` и соседние | каталог, вкладки, форма, поле, баланс, волны |
| Иконки интерфейса | `addons/content_editor/ContentEditorTheme.cs` | доступ к EditorIcons с проверкой имени |
| Примитивы UI | `addons/content_editor/primitives/` | строки свойств, контекстные вкладки, таблица и граф |
| Состояние | `scripts/data/editor/ContentEditorStore.cs` | тексты, черновики, provenance, внешние правки |
| Схема полей | `scripts/data/editor/ContentSchema.cs` | что показывает форма, включая поля волн |
| Запись TOML | `scripts/data/editor/TomlPatchWriter.cs` | точечная правка ключей и блоков `[[name]]` без потери комментариев |
| Отрисовка зданий | `scripts/draw/BuildingVisual.cs` | общий код с Building._Draw |

Неочевидные ограничения Godot и решения, принятые после обнаруженных дефектов,
собраны в [`docs/content-editor-tips.md`](content-editor-tips.md).

Черновики открытых вкладок подставляются в сборку через `ContentCompiler.CompileWithOverrides`. Глобальный `Content.Catalog` обновляется только после успешного Apply или явного Reload.

## Запуск

1. Сборка проекта в редакторе (Godot подхватывает C#).
2. Вкладка **Content** на панели режимов.
3. Если вкладки нет: `Проект → Настройки проекта → Плагины` — включить «Content editor».

## Режим Entities

- Слева — отдельные вкладки каталога: Units, Buildings, Weapons, Tools. Запись имеет вид `файл.toml (Отображаемое имя)` и иконку силуэта.
- Кнопка **Open fullscreen** переносит редактор в отдельное полноэкранное окно. Кнопка **Dock in editor** и закрытие отдельного окна возвращают его во вкладку **Content**.
- Щелчок по записи открывает нативную вкладку Godot с крестиком внутри неё. Активная вкладка выделена контрастнее соседних. Повторное открытие активирует существующую вкладку; несохранённые файлы помечаются `*`.
- По центру — общее измерительное поле: все открытые сущности с включённым Show on field рисуются вместе. Активная выделена; объекты перетаскиваются. Кнопка **Layout** на панели поля расставляет их автоматически.
- Справа — форма свойств по секциям TOML. Сверху поле **Filter fields…**: отбор по подписи и ключу сохраняется при смене сущности. Обычная строка имеет колонки названия, значения и источника; длинные значения переносятся под заголовок.
  У каждого поля указан источник значения:

| Метка | Смысл |
|-------|--------|
| in this file | ключ записан в текущем файле |
| inherited | значение пришло из родительского определения |
| from vars | ссылка на `*.vars.toml` или значение из него |
| default | в файлах ключа нет, взято из кода |

- Изменение унаследованного поля автоматически создаёт локальное значение.
- Кнопка `↶` удаляет локальный ключ (и пустую секцию), после чего снова действует наследование.
- Кнопка `↗` открывает родительское определение в редакторе контента либо панель значений `*.vars.toml`.
- Для `*.vars.toml` кнопка `↗` открывает нижнюю контекстную вкладку со всеми значениями
  файла. Кнопка **Relations** открывает граф наследования, файлов переменных, оружия и рабочих
  инструментов. Контекстные вкладки закрываются крестиком. При выборе другого юнита граф
  обновляется, а вкладка vars сохраняется, если новый юнит ссылается на тот же файл.
- Связанные инструменты открываются отдельными вкладками из блока внизу формы.

### Область действия кнопок

Кнопка стоит рядом с тем, на что действует, и выключается, когда действовать не на что; подсказка выключенной кнопки называет причину.

| Полоса | Область действия | Кнопки |
|--------|------------------|--------|
| Верхняя, с меткой Project | весь проект | **Reload all files**, переключатель отдельного окна |
| Заголовок панели свойств, с именем активного файла | активная вкладка | **Apply**, **Revert**, **Reload file**, **Close** |
| Панель измерительного поля | содержимое поля, то есть все открытые вкладки | Grid…Work, **Ruler**, **Fit all**, **1:1**, **Layout** |

- **Apply** пишет только локальные переопределения в `.toml`, сохраняя комментарии, затем пересобирает каталог. **Revert** возвращает черновик к тексту с диска. Обе доступны лишь при несохранённых правках активной вкладки.
- **Reload file** перечитывает с диска только активный файл; **Reload all files** — все `.toml` проекта, сохраняя черновики.

### Внешние правки файлов

Редактор сверяет метки времени `.toml` с диском:

- при возврате на вкладку **Content**;
- при возврате фокуса в окно Godot;
- после сигналов `EditorFileSystem.FilesystemChanged` (с короткой паузой).

Если вкладка без локальных правок — текст подтягивается молча. Если есть несохранённый черновик — диалог: Reload from disk или Keep draft.

### Измерительное поле

- Сетка: 1 клетка = 1 игровая единица = `Const.Unit` (64) пикселя.
- Линейки по краям, масштабная отметка «1 cell».
- Переключатели: Grid, Sizes, Cells, Margin, Vision, Attack, Work.
- Колесо — масштаб, средняя кнопка — панорамирование, **Fit all** / **1:1** / **Layout**, инструмент **Ruler** для расстояний между точками.

## Панели

Каталог, измерительное поле, контекстные страницы, форма свойств активной сущности и обе таблицы баланса заключены в панели с рамкой и заголовком (`primitives/EditorPanel.cs`). Кнопка, помещённая в заголовок панели, действует на её содержимое: так область действия видна по расположению, а не запоминается.

Панель активной сущности охватывает только форму её свойств. Измерительное поле стоит отдельной панелью, поскольку показывает все открытые вкладки сразу и одной сущности не принадлежит.

Фон и рамка панелей выводятся из базового цвета темы редактора (`interface/theme/base_color`), поэтому следуют выбранной пользователем теме Godot и не вносят собственного оттенка.

## Режим Balance

Две таблицы друг под другом: Player сверху, Enemy снизу (`UnitClass.Enemy`). Общие поиск, тип (All / Mobile / Structures), роли Attackers и Builders. Вид колонок задаётся элементом View: заготовки All / Combat / Economy / Construction, туглы Fields по секциям Identity / Combat / Economy / Construction и сохранение своего набора. Если набор колонок не совпадает ни с одной заготовкой, в списке видов показывается Custom view. Кнопка **Save view…** при выбранном сохранённом виде спрашивает, обновить его или сохранить набор колонок как новый вид; встроенные виды не перезаписываются. Сортировка по умолчанию — Army Power по убыванию, на заголовке активной колонки стоит ▲ или ▼. Колонки идут в порядке туглов: Name, Id, Class, Army Power, Health, DPS, Range, Vision, Speed, Size, Cost, Health/Metal, Net Energy, Net Metal, Expansion Power, Build Power. Время сборки не показывается: оно зависит от строителя, а не от самой сущности. Иконка в колонке Name — тот же силуэт, что в строительной панели. Двойной щелчок открывает сущность во вкладках.

## Режим Waves

Слева карта применимости волн по шкале террора, справа инспектор выбранной волны
(`addons/content_editor/ContentEditorWaves.cs`).

### Карта

- Ось сверху — террор от нуля до наибольшей конечной границы среди всех `resources/waves/*.toml`. Переключатель **Log scale** сжимает ось логарифмически: одна волна с границей в десятки тысяч иначе прижимает все прочие к нулю.
- Строка — одна волна: слева имя и теги, справа полоса от `terror_range[0]` до `terror_range[1]`. Открытый верхний предел (`-1`) обозначен клином на конце полосы, открытый нижний — знаком `◂` у начала шкалы. На полосе написан бюджет и, если задан, прирост за очко террора.
- Ползунок **terror** ставит вертикальную отметку и приглушает волны, которые при этом показателе не подходят. Так виден участок шкалы, на котором не применима ни одна волна.
- Звёздочка у имени означает несохранённый черновик, красная обводка полосы — что черновик не проходит проверки содержимого и записан быть не может.
- Щелчок выбирает волну и открывает её вкладку; двойной щелчок дополнительно открывает файл в системном редакторе.

Карта строится по снисходительному разбору черновиков (`ContentEditorStore.WaveOverviews`), а не по собранному каталогу: `ContentCompiler` отбрасывает волну целиком при любой ошибке проверки, и строка исчезала бы посреди правки.

### Инспектор

Все поля волны редактируются на месте; кнопки **Apply**, **Revert**, **Reload** и открытие файла стоят в заголовке панели инспектора и действуют на выбранную волну.

- Корневые ключи: имя, `terror_range` (два числа через запятую, `-1` — граница отсутствует), бюджет, прирост за очко террора, множитель и разброс отдыха, теги, `prefer_next`.
- Секция **Spawn shape** — переопределения формы появления; пустое поле означает, что ключа в файле нет и действует умолчание подсистемы.
- Метка справа от поля говорит, записан ключ в файле или взят по умолчанию; кнопка возврата удаляет локальный ключ.
- Блоки `[[unit_list]]` показаны отдельными панелями. Режим выбирается списком (`allow` сужает допустимое, `deny` вычитает, `limit` задаёт только долю бюджета), доля бюджета правится числом, а состав — выбором из перечня видов противника, отчего опечатка в идентификаторе невозможна. Блок добавляется кнопкой **Add unit list** и удаляется крестиком в заголовке блока вместе с относящимся к нему комментарием.

Правка идёт в черновик вкладки, как и для юнитов, поэтому волна одновременно появляется во вкладках режима **Entities** и участвует в сборке до записи на диск.

## Ограничения первой версии

Не входят: создание и удаление файлов сущностей и волн, редакторы buildbar / тегов / `*.vars.toml`, пакетное редактирование строк таблицы, боевая симуляция.
