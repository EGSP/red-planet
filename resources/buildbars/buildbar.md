# Строительные панели

Здесь лежат определения строительных панелей — по файлу `.toml` на панель. Юнит ссылается
на свою панель полем `UnitDef.Buildbar`, в котором стоит идентификатор, а не путь к файлу.
Отдельного списка доступных построек юнит не держит: **панель и есть ответ на вопрос, что
этот строитель умеет строить.**

Разбор — `scripts/data/BuildbarLoader.cs`, раскладка — `scripts/ui/BuildbarLayout.cs`,
отрисовка — `Hud`.

---

## Формат

```toml
id = "commander"
priority = 1

[[sections]]
id = "economy"
title = "Экономика"
order = 0
cells = [
	{ x = 0, y = 1, build = "generator_t2" },
	{ x = 1, y = 1, build = "assembler" },
	{ x = 0, y = 0, build = "generator" },
	{ x = 1, y = 0, build = "factory" },
]
```

| Поле | Где | Смысл |
|---|---|---|
| `id` | панель | Идентификатор, на него ссылается `UnitDef.Buildbar` |
| `priority` | панель | Главенство при слиянии, **чем меньше — тем важнее** |
| `id` | секция | Ключ, по которому секции разных панелей узнают друг друга |
| `title` | секция | Заголовок на экране |
| `order` | секция | Место секции на панели: чем меньше, тем выше |
| `x`, `y`, `build` | ячейка | Координата и `Id` постройки из `resources/buildables/` |

**Счёт идёт от левого нижнего угла секции:** `X` растёт вправо, `Y` — вверх. На экране
порядок обратный, и переворачивает его отрисовка, чтобы нижний ряд справочника оказался
нижним и на панели. Пустая ячейка никак не описывается — её просто нет в списке.

### Почему TOML, а не YAML

Определения правят точечно и часто, поэтому цена опечатки должна быть местной. В TOML нет
значимых отступов: промах пробелом портит одну строку, а не структуру всего файла. Типы
однозначны — постройка с идентификатором вроде `no` или `on` останется строкой, тогда как
YAML превратил бы её в логическое значение. Вложенность здесь мелкая, всего два уровня,
поэтому главная слабость TOML — неуклюжесть на глубоких структурах — не проявляется.
И комментарии: соглашение ниже требует пояснений прямо рядом со спорной ячейкой.

## Слияние при выделении нескольких юнитов

Панель на экране одна, а выделить можно кого угодно и в каком угодно составе. Поэтому
панели всех выделенных строителей складываются:

1. Панели сортируются по `priority` по возрастанию, при равенстве — по `id`. Порядок,
   в котором игрок щёлкал по юнитам, на разметку не влияет.
2. Секции узнают друг друга по `id`. Заголовок и место секции берёт та панель, что ввела
   секцию первой, то есть самая важная из объявивших её.
3. Ячейки накладываются по координатам.

**Спор за ячейку.** Если накладываемая панель метит в занятую ячейку другой постройкой,
занятая остаётся на месте, а пришедшая вставляется сразу за ней, сдвигая хвост строки
вправо. Сдвиг живёт внутри одной строки: соседние строки той же секции он не задевает,
и строки становятся разной длины — это нормально и ожидаемо.

Правило подчинено одному требованию: **у постройки из более важной панели позиция
не меняется никогда.** Иначе выделение фабрикатора вместе с коммандером сдвигало бы
кнопки коммандера, и мышечная память игрока не нарабатывалась бы вовсе.

Одна и та же постройка, объявленная в двух панелях, кладётся один раз — на позицию,
заданную более важной панелью.

## Соглашение: держите координаты согласованными

**Позиции одной и той же постройки должны совпадать во всех панелях, где она есть.**
Разрешение споров — это страховка от ошибки, а не рабочий приём: пользоваться им как
средством раскладки значит получить панель, которая перестраивается от состава выделения.

Поскольку каждая панель описана целиком в своём файле, общие секции неизбежно повторяются
в нескольких файлах. Это осознанная плата за то, что панель читается и правится в одном
месте. Отсюда практика:

- **Правя общую секцию, правьте её во всех панелях сразу.** Сверяйтесь по `id` секции.
- **Пропуски в координатах — норма.** Если у этого строителя постройки нет, а у более
  важного она есть, координату просто не занимайте: `x = 1` может отсутствовать при
  занятых `x = 0` и `x = 2`.
- **Пропущенные ряды — тоже норма.** Секция может иметь ячейки при `y = 0` и `y = 2`,
  не имея ни одной при `y = 1`.
- Проверка простая: откройте два файла рядом и убедитесь, что у общих построек совпадают
  и `x`, и `y`.

Сейчас `economy` и `defence` описаны одинаково у коммандера и фабрикатора, а секция
`units` есть только у коммандера — юнитов фабрикатор не строит.

## Что где лежит

```
resources/buildbars/
├─ buildbar.md          — этот документ
├─ commander.toml       — панель коммандера,  priority 1
└─ fabricator.toml      — панель фабрикатора, priority 2
```

Панель появляется на экране только тогда, когда среди выделенных есть юнит, умеющий
строить. Без выделения панели нет вовсе — как нет и получателя приказов: правый щелчок
без выделения не делает ничего.

**При настройке экспорта не забудьте про `*.toml`:** это не ресурс Godot, а обычный файл,
и в сборку он попадёт только если добавлен в фильтр включаемых файлов пресета экспорта.
